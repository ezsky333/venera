# 部署指南

## 前置条件

- NAS 支持 Docker（群晖 / 威联通 / Unraid / TrueNAS / 任意 Linux）
- 建议 **2GB 内存**、**至少 10GB 可用空间**（漫画文件按需增长）
- 若走公网访问，建议放在反向代理（Nginx / Caddy / Traefik）后面并启用 HTTPS

---

## 一、最简部署（docker compose）

```bash
# 1. 准备目录
mkdir -p /volume1/docker/venera-nas/{data,library}
cd /volume1/docker/venera-nas

# 2. 生成一份 compose 文件
cat > docker-compose.yml <<'EOF'
services:
  venera-nas:
    image: ghcr.io/venera-app/venera-nas:latest
    container_name: venera-nas
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      VENERA_TOKEN: "换成一个足够长的随机串"
      VENERA_WEBDAV_USER: "venera"
      VENERA_WEBDAV_PASS: "也换掉"
      TZ: "Asia/Shanghai"
    volumes:
      - ./data:/data
      - ./library:/library
EOF

# 3. 启动
docker compose up -d

# 4. 验证
curl http://127.0.0.1:8080/api/v1/ping
```

> **镜像架构**：CI 会同时构建 `linux/amd64` 与 `linux/arm64`，Docker 会自动选择。

### 群晖 / 威联通注意

- 群晖的 `docker` 用户组需要对该目录有读写权限：
  ```bash
  sudo chown -R 1000:1000 /volume1/docker/venera-nas
  ```
  （镜像以 UID 1000 运行，见 `Dockerfile` 的 `adduser -u 1000`）
- 威联通的 Container Station 可直接导入 `docker-compose.yml`。

## 二、安装漫画源

### 方式 A：让 App 同步过来（推荐）

App 的 `.venera` 同步包**已经包含** `comic_source/*.js` 和 `*.data`（登录态），
服务端会自动安装。

在 App 里：**设置 → App → Data Sync → 填 WebDAV 地址**
（`http://<nas>:8080/webdav/`，凭据用 `VENERA_WEBDAV_USER/PASS`），
上传一次即可。

### 方式 B：手动拷贝

```bash
git clone --depth 1 https://github.com/venera-app/venera-configs /tmp/vc
cp /tmp/vc/*.js /volume1/docker/venera-nas/data/sources/
rm -f /volume1/docker/venera-nas/data/sources/_template_.js
rm -f /volume1/docker/venera-nas/data/sources/_venera_.js

curl -X POST -H "Authorization: Bearer <token>" \
     http://127.0.0.1:8080/api/v1/sources/refresh
```

### 验证源可用性

```bash
# 列出已装源
curl -H "Authorization: Bearer <token>" http://nas:8080/api/v1/sources

# 探测某个源 + 某部漫画
curl -X POST -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
     -d '{"comicId":"<漫画ID>"}' \
     http://nas:8080/api/v1/sources/manga_dex/probe
```

返回 `{"ok":true,"title":"...","chapters":227}` 即表示该源可用。

## 三、App 端配置

1. 安装本仓库构建的 APK（见 [CI 产物](../../.github/workflows/venera-apk.yml)）
2. **设置 → App → NAS Server**
3. 填入服务地址（如 `http://192.168.1.10:8080`）与 Token
4. 点 **Continue**
   - 状态卡片变绿 → 已连接
   - 探测失败会自动回滚，不会破坏原配置
5. 连接成功后自动做一次全量对齐

之后：

- 收藏、阅读进度会自动增量同步
- 详情页多出一个 **NAS** 按钮，点击即让服务端下载
- 阅读时若 NAS 已缓存，优先从 NAS 读

## 四、迁移已有数据

### 从 WebDAV 备份导入

```bash
docker run --rm \
  -v /volume1/docker/venera-nas/data:/data \
  -v /volume1/docker/venera-nas/library:/library \
  -v /path/to/backup.venera:/tmp/backup.venera \
  ghcr.io/venera-app/venera-nas:latest \
  -import -archive /tmp/backup.venera
```

导入内容：收藏夹、阅读历史、源脚本、源登录态、Cookie、部分设置。

### 直接 PUT 到 WebDAV

服务端监听 `.venera` 文件写入并自动异步导入，适合让 App 直接上传。

## 五、反向代理

### Caddy（自动 HTTPS，最省心）

```caddyfile
nas.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

### Nginx

```nginx
server {
    listen 443 ssl http2;
    server_name nas.example.com;

    client_max_body_size 512m;        # 同步包可能较大

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
        # 大图/长任务：放宽超时
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

同时设置：

```yaml
environment:
  VENERA_PUBLIC_BASE_URL: "https://nas.example.com"
```

否则服务端生成的图片 URL 会是内网地址，外网客户端打不开。

## 六、运维

### 日志

```bash
docker logs -f venera-nas
```

JSON 格式，关键字段：`msg`、`method`、`path`、`status`、`err`。

### 健康检查

```bash
curl http://127.0.0.1:8080/healthz      # ok
```

### 常用 API

```bash
T="Authorization: Bearer <token>"

# 服务概览（源数量、库大小、游标）
curl -H "$T" http://nas:8080/api/v1/info

# 任务队列
curl -H "$T" "http://nas:8080/api/v1/jobs?status=running"
curl -H "$T" http://nas:8080/api/v1/jobs/3

# 取消任务
curl -X POST -H "$T" http://nas:8080/api/v1/jobs/3/cancel

# 库内容
curl -H "$T" http://nas:8080/api/v1/library

# 某漫画已缓存的章节
curl -H "$T" http://nas:8080/api/v1/library/jm/<comicId>

# 删除某章
curl -X DELETE -H "$T" http://nas:8080/api/v1/library/jm/<comicId>/<chapterId>

# 批量排队所有收藏
curl -X POST -H "$T" http://nas:8080/api/v1/download/favorites

# 已连接的客户端
curl -H "$T" http://nas:8080/api/v1/sync/clients
```

### 存储管理

- 库大小：`GET /api/v1/info` 的 `libraryBytes`
- 每章大小：`GET /api/v1/library/<source>/<comicId>` 的 `bytes`
- 按需删除：`DELETE /api/v1/library/<source>/<comicId>/<chapterId>`
- 限制总量：`VENERA_MAX_LIBRARY_BYTES`

## 七、故障排查

| 现象 | 排查 |
|---|---|
| App 连不上 | `curl http://nas:8080/api/v1/ping`；检查防火墙/端口映射 |
| 401 | Token 不一致；检查 `VENERA_TOKEN` 与 App 里填的是否相同 |
| 源列表为空 | `data/sources` 是否为空；跑 `sources/refresh` |
| 下载任务全部失败 | 看 `docker logs` 的 `source` 日志；多数是站点不可达或需登录 |
| `source not found` | 该源未安装，或 App 同步包里没有 |
| 图片 URL 打不开 | 反代场景未设 `VENERA_PUBLIC_BASE_URL` |
| 收藏对不上 | 检查 `source_type_map` 是否被 App 上报过 |
| 容器内存涨得快 | 降低 `VENERA_WORKERS` 与 `VENERA_DOWNLOAD_CONCURRENCY` |

### 关于 Cloudflare

若某源报 `CloudflareException`：

1. 在 App 里打开该源，手动过一次验证
2. App 会把 `cf_clearance` 存进 `cookie.db` 与 `ua`
3. 通过 WebDAV 同步到服务端（或 `POST /api/v1/sync/push` 的 `source.cookie`）
4. 服务端会带上该 Cookie 与 UA 请求

仍失败则该源只能"仅 App 端下载"。这是容器方案的固有限制
（过 CF 需要真实浏览器指纹）。

## 八、资源占用参考

| 场景 | CPU | 内存 | 备注 |
|---|---|---|---|
| 空转 | <1% | ~30MB | 仅 HTTP + SQLite |
| 单任务下载 | 5-15% | 80-150MB | 一个 goja VM |
| 3 并发下载 | 20-40% | 200-350MB | 默认配置 |
| 解析 200+ 章的漫画 | 瞬时 40% | +50MB | 章节列表 JSON |

镜像大小：**约 25MB**（alpine + 静态二进制）。

## 九、安全建议

1. **必须设置 `VENERA_TOKEN`** —— 否则任何能访问端口的人都能读写你的库
2. 公网访问**必须走 HTTPS** —— 同步包含 Cookie 与登录态
3. 不要把 `/data` 目录暴露给其他人 —— 里面有账号凭据
4. 定期备份 `/data`（`nas.db` + `sources/`）—— 库文件丢了可以重下，元数据丢了要重配
