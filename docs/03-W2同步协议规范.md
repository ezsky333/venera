# W2 同步协议规范

> 适用版本：`protocol: "w2"`
> 客户端：`lib/utils/nas_sync.dart` ｜ 服务端：`internal/syncer/`

## 为什么不用 WebDAV 整包覆盖

App 原本的 `DataSync`（`lib/utils/data_sync.dart`）把 SQLite + 配置打成一个 zip
整体上传/覆盖。这套机制在**单设备**下可用，但多设备时必然互相覆盖，
且服务端无法回传任何指令（"这章已缓存"/"去下载它"）。

W2 改为**操作日志（op log）**模型：

| 维度 | W1 (WebDAV) | W2 (本协议) |
|---|---|---|
| 传输 | 整个数据库 zip | 只传增量操作 |
| 冲突 | 后者覆盖前者 | 语义合并（集合求并 / LWW） |
| 多设备 | 互相覆盖 | 天然支持 |
| 服务端→客户端 | 无 | 游标拉取 + 快照 |
| 首次接入 | 下载全量 | 快照或从头回放 |

W1 仍然保留（`/webdav/`），用于老客户端接入与数据迁移。

## 数据模型

服务端状态由 5 类实体组成：

| 实体 | 主键 | 合并语义 |
|---|---|---|
| `favorites` | `(folder, source, comicId)` | 集合语义，删除即删除 |
| `histories` | `(source, comicId)` | **LWW**，按客户端时间 |
| `source_data` | `source` | 按键合并（不整体覆盖） |
| `source_cookies` | `(source, name, domain, path)` | 按键覆盖 |
| `settings` | `key` | 覆盖 |

所有写操作都会进入 `ops` 表，获得一个**单调递增的 `id`**。
这个 `id` 就是客户端拉取用的**游标**。

## 端点

### `POST /api/v1/sync/push`

提交一批本地操作。

```jsonc
{
  "clientId": "dev-a1b2c3",        // 必填，设备唯一标识
  "deviceName": "android",          // 可选，仅运维识别
  "lamport": 1700000000000,         // 客户端逻辑时钟
  "ops": [
    { "type": "fav.add",        "payload": { ... } },
    { "type": "fav.remove",     "payload": { ... } },
    { "type": "fav.move",       "payload": { ... } },
    { "type": "history.update", "payload": { ... } },
    { "type": "source.data",    "payload": { ... } },
    { "type": "source.cookie",  "payload": { ... } },
    { "type": "setting.update", "payload": { ... } }
  ]
}
```

响应：

```jsonc
{
  "applied": 3,                     // 真正改变了状态的操作数
  "cursor": 42,                     // 服务端当前游标，客户端应保存
  "serverLamport": 1700000000123,   // 用于校准本地时钟
  "warnings": ["unknown op type \"x.y\""]  // 被忽略的操作
}
```

**关键行为**

- **单条失败不中断整批**：一个坏操作只产生 warning，其余照常落库。
- **幂等**：重复提交同一条 `fav.add` 不会产生重复收藏。
- **只有真正改变状态的操作才进日志**（保证广播一致性）。

### `GET /api/v1/sync/pull?cursor=<n>&clientId=<id>&limit=<n>`

增量拉取 `id > cursor` 的操作。

```jsonc
{
  "ops": [
    { "id": 41, "clientId": "dev-x", "type": "fav.add",
      "lamport": 1, "payload": {...}, "at": "2026-04-05T..." }
  ],
  "cursor": 41,
  "hasMore": false,
  "serverLamport": 1700000000123,
  "resyncRequired": false
}
```

- **回显抑制**：默认不返回该 `clientId` 自己的操作（避免抖动）。
  全量恢复场景可加 `includeSelf=1`。
- **`resyncRequired`**：为 true 表示游标已被裁剪，客户端必须走快照。

### `GET /api/v1/sync/snapshot`

完整状态，用于首次接入或游标过期。

```jsonc
{
  "favorites": { "我的收藏": [ {...}, {...} ] },
  "histories": [ {...} ],
  "settings": { "k": ... },
  "sources": [ {"key":"jm","name":"禁漫天堂","version":"1.4.0"} ],
  "cursor": 42,
  "at": "2026-04-05T..."
}
```

### `POST /api/v1/sync/source-type`

上报 `sourceKey → hashCode` 的权威映射。**这是长期兼容的关键**：
服务端不依赖 Dart 哈希算法的稳定性。

```jsonc
{ "mapping": { "jm": 769844263, "ehentai": 385625716 } }
```

## 各操作的载荷

### `fav.add`

```jsonc
{
  "folder": "我的收藏",
  "source": "jm",
  "comicId": "12345",
  "title": "标题",
  "author": "作者",
  "cover": "https://...",
  "tags": ["作者:xxx"],
  "sourceType": 769844263
}
```

### `fav.remove`

只需定位键：

```jsonc
{ "folder": "我的收藏", "source": "jm", "comicId": "12345" }
```

### `fav.move`

```jsonc
{ "fromFolder": "A", "toFolder": "B", "source": "jm", "comicId": "12345" }
```

### `history.update`

```jsonc
{
  "source": "jm", "comicId": "12345",
  "title": "标题", "cover": "...",
  "sourceType": 769844263,
  "ep": 3, "page": 7, "group": 1,
  "readEpisodes": ["1","2","3"],
  "maxPage": 20,
  "at": 1700000000000        // 客户端时间，LWW 依据
}
```

> `at` 缺失时服务端用当前时间。**LWW 比较的是 `updated_at`**，
> 更旧的操作会被丢弃且不计入 `applied`。

### `source.data`

承载源的登录态（对应 App 的 `comic_source/<key>.data`）：

```jsonc
{ "source": "ehentai", "data": { "account": [...], "token": "..." } }
```

服务端按键**合并**，不会抹掉其他设备的字段。

### `source.cookie`

```jsonc
{
  "source": "jm",
  "cookies": [
    { "name":"cf_clearance", "value":"...", "domain":".jmcomic.me",
      "path":"/", "expires":1700000000000, "secure":true }
  ]
}
```

### `setting.update`

```jsonc
{ "key": "followUpdatesFolder", "value": "追更" }
```

## 客户端接入流程

```
首次连接：
  1. GET  /api/v1/ping            → 确认协议版本 w2
  2. GET  /api/v1/sync/snapshot   → 重建本地状态，记录 cursor
  3. POST /api/v1/sync/source-type → 上报所有源的 hashCode

日常使用：
  本地改动（收藏/进度） → 入队
    ↓ 500ms 防抖 + 同对象去重
  POST /api/v1/sync/push → 更新本地 cursor
  定时/启动/前台切换
    ↓
  GET  /api/v1/sync/pull?cursor=<本地> → 应用其他设备的操作
```

**去重策略（客户端）**：同一 `(source, comicId)` 的 `history.update` 与同一
`source` 的 `source.data` 只保留队列中最后一条。收藏增删是**对立操作**，
不参与去重（否则会丢失语义）。

## 读取路径（NAS 优先）

```
打开章节
  ↓
本地已下载？ ──是──→ 读本地文件
  │否
  ↓
GET /api/v1/chapter?source=&comicId=&chapterId=
  ├─ cached=true  → images = pages[]（直接加载）
  └─ cached=false → 回退到源的 loadComicPages()
```

**约定：NAS 绝不能成为阅读的阻塞点。** 任何超时/错误都静默降级。

## 版本演进

- 新增操作类型是向后兼容的：旧客户端收到未知类型应忽略。
- 删除/重命名字段需要 `protocol` 升版（`w2` → `w3`）。
- 操作日志可按 `SyncRetention` 裁剪；被裁剪后旧游标会得到 `resyncRequired`。
